# 通用工作流 Runner

## 定位与铁律

本 skill 是所有 `knowledge/shared/workflows/<工作流名>/workflow.yaml` 的统一执行器。

- **薄执行器**：只做四件事——调度（按 stages 逐段执行）、门禁（gate 协议）、记账（runs 档案）、续跑。业务怎么做由各阶段 `tool` 指定的 skill 决定，本 skill 不重复、不覆盖业务规则
- **YAML 是唯一流程权威**：每次执行前重新读取 workflow.yaml（不依赖记忆中的旧版本）；本文与 YAML 冲突时以 YAML 为准
- **通用规则同步遵守**：`knowledge/shared/workflows/README.md` 的六条通用规则视为本 skill 指令的一部分

## 第一步：解析与启动

1. 从用户输入解析：**工作流名** → 定位 `knowledge/shared/workflows/<工作流名>/workflow.yaml`（文件名固定）；找不到时列出登记表中的可用工作流，不臆测
2. 读取 YAML，解析 `input` / `scope` / `stages` / `gate_protocol` / `metrics`
3. **入口校验**：逐项核对 `input` 所列输入物是否齐备（文件存在、路径正确）；缺任一项 → 🛑 **STOP** 停在门口，列出缺什么，不进入 S1
4. **范围登记**：用户声明了范围（"仅 XX，其余不处理"）则全程生效——所有阶段只处理该范围，禁止顺带生成范围外内容；未声明则默认整份输入
5. 向用户回显一行启动确认：工作流名 / 项目 / 输入 / 范围 / 将执行的阶段链

## 第二步：运行档案（先建档，再干活）

在 `knowledge/shared/workflows/runs/` 下创建 `<YYYYMMDD>-<项目>-<需求或模块标识>.md`：

```markdown
# run-<YYYYMMDD>-<序号> · <工作流名>（workflow.yaml 版本号）
项目: <项目>   输入: <路径>   范围: <范围或"整份">   执行人: <用户>
| 阶段 | 状态 | 产物/结论 | 备注 |
|---|---|---|---|
| S1 | 未开始 | | |
| ...（按 YAML stages 生成全部行）|
```

- 每完成一段即更新对应行（✅ 完成 / ⏸ 等待审核 / 🔁 回炉中 / ⏭ 跳过+原因）
- 回炉时在备注记：不过门的条目、回炉路径（A/B/C）、原因——这是 metrics 与错题本的原料

## 第三步：阶段执行规则

按 stages 顺序逐段执行：

**`executor: ai` 的阶段**
- 必须通过 Skill 工具**真实调用** `tool` 字段指定的 skill，禁止内联模拟或"按该 skill 的精神"自行输出
- 阶段产物路径/结论写入运行档案后进入下一段
- 该 skill 自带的强制步骤（如知识库提取表）不得代其省略

**`executor: human` 的阶段（🔴 CHECKPOINT · gate，最高优先级规则）**
- 呈现三样东西，**分开呈现**：① 产物路径；② AI 自查证据（格式"AI 自查：通过/不通过 + 证据"，判断类条目只给抽样证据不下结论）；③ **复选框全部留空**的 gate 验收清单
- 🛑 **STOP** · 呈现后**本轮回合必须结束**，等待审核人回复。以下行为一律禁止：
  - 代勾任何 `[x]`（包括自查已通过的项）
  - 把用户的沉默、模糊回复（"嗯""看看吧"）或与审核无关的消息当作放行
  - 未获明确"通过"（整体或逐条）就执行下一阶段——**即使用户说"直接出结果"，也必须先完成本 gate 的明确确认**
- 审核人回复"不过/回炉" → 严格按该阶段 `on_fail` 声明的路径执行（A 按结论回炉 / B 人工手改后重读文件 / C 混合时先重叠判定再合并），回炉后按 YAML 要求重跑前置查漏、重新过本 gate
- 审核人手改过产物 → 必须重新从磁盘读取文件，禁止用记忆中的旧内容

**收尾阶段（如 S7 记账）**
- 与其他 ai 段同等强制，禁止因"主要产物已交付"而省略；按 YAML 的 action 执行（含当场询问人时——未获答复标"待补"，禁止臆测代填）

## 第四步：续跑

用户说"从 S<N> 继续"时：
1. 优先在 `runs/` 中找到对应运行档案，核对已完成阶段与产物路径；找不到档案则要求用户提供已完成阶段的产物路径，**补建档案**后再继续
2. 重新读取 workflow.yaml（可能已更新）与已完成阶段的产物文件（不依赖旧会话记忆）
3. 从 S<N> 正常执行，档案接着记

## 禁止行为

- 跳过或合并任何 gate；代勾复选框；自查结论冒充审核结论
- 不调用 tool 指定的 skill 而自行产出该阶段内容
- 修改 workflow.yaml（流程变更走 owner 评审，不在执行中发生）
- 超出用户声明的范围顺带生成内容
- 跳过运行档案或收尾记账阶段

## 调用示例

```
/run-workflow 用例设计  项目：acuhmi_1_7  需求文档：requirements/summaries/v2.00_20260519.md
/run-workflow 用例设计  项目：acuhmi_1_7  需求文档：<路径>  范围：仅 §3.4 SNMP，其余模块不处理
/run-workflow 用例设计  从 S4 继续  项目：acuhmi_1_7  审定脑图：<路径>
```
