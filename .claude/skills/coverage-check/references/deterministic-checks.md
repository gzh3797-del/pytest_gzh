**版本绑定**：本层规则引用的「SKILL 第 X 步」随 strategy-design / testcase-design 迭代会漂移，核对时以两个生成 skill 的**当前实际定义为准**；下方标 `〔待定〕` 的项须在执行时现场核对生成 skill。

## 脑图确定性校验（D1–D10）

解析 XMind `content.xml` 即可判定。

| # | 校验项 | 规则依据 |
|---|--------|----------|
| D1 | 存在「功能概述」节点，且含 功能定位 / 工作流程 / 关键约束 三条叶子 | strategy-design 第零步 |
| D2 | 根节点标题含「共预估 X 条」；每个二级分组含「预估 X 条」；分组求和 = 根节点数 | 第六步 |
| D3 | 叶子「X个用例」标注解析后，分组内求和（未标注计 1）= 分组预估数 | 第六步 |
| D4 | 同层节点标题无重复 | — |
| D5 | 〔待定〕叶子不含禁止句式：以「系统支持」开头、通篇仅名词（如「Interval 配置」）、「功能正常 / 配置正确」 | 第二步禁止写法（规则待双组确认） |
| D6 | 🔴 泛称检测：叶子含「设备 / 下挂设备 / 电表」泛称而无具体型号，且未注明「任一型号 + 理由」 | 语言规范·硬性 |
| D7 | 遍历类叶子不含「相关 / 部分 / 等」模糊范围词 | 格式规范 |
| D8 | `[补充]` 前缀格式规范（前缀在句首、无变体写法） | 第四步 |

| D10 | 二级分组顺序符合固定序：启停入口 → 基础参数校验 → 附属配置 → 核心操作 → 联动规则 → 批量操作 → 导入导出 → 兼容异常（缺失分组可跳过，已有分组相对顺序不得错乱） | 格式硬约束·分组顺序 |

## 用例确定性校验（D1–D15）

解析 `.xlsx`（openpyxl）即可判定。

| # | 校验项 | 规则依据 |
|---|--------|----------|
| D1 | 〔待定〕列齐全且顺序与 testcase-design 列定义完全一致（含「是否能自动化」位于「完成自动化」前）；**列数以 testcase-design 当前列定义为准**（材料写 16、题集标题写 17，须现场核对） | testcase-design 第一步 |
| D2 | 〔待定〕编号格式合规：`TestCase_<项目缩写>_XXX_XXX_XXX`；FTS 编号与用例编号仅前缀不同；项目缩写与当前项目名匹配。**按本仓库（电表组）编号口径**（CLAUDE.md 高频约定 10/12），双组差异待确认 | testcase-design 第二步 |
| D3 | 全表编号无重复，且与 `testcase/` 已有用例表编号无冲突、同模块从已有最大序号续接 | 第二步·编号冲突检查 |
| D4 | 🔴 每条用例「测试步骤」「预期结果」均非空，且按 `1. 2. 3.` 多行编号 | 红线 + 第三步 |
| D5 | 预期结果编号 ⊆ 步骤编号集合（可跳号，不得错位 / 超出步骤号） | 第三步 |
| D8 | 「是否能自动化」∈ {是, 否}；标「否」者「备注」列非空 | 第四步补充 |
| D9 | 🔴 泛称检测：步骤 / 预期含「设备 / 下挂设备 / 电表」泛称而无具体型号，且未注明「任一型号 + 理由」 | 核心原则 5（硬性） |
| D10 | 模糊黑词检测：步骤 / 预期不含「相应页面 / 合法值 / 检查是否正常 / 验证功能正确 / 配置生效（无回读对象）/ 等 / 相关项 / 完整显示」 | 反例 4、11 + 写法规范 |
| D13 | 来源脑图中标「X个用例」的分支，实际生成数与标注严格一致；标题含「待确认」的子树无任何对应用例。**无脑图的纯需求直转场景跳过 D13，报告注明** | 第五步补充、规则 5 |
| D14 | 〔待定〕产物随附「知识库提取表」，各类行齐全、无空行、事实注明来源；**类数以 testcase-design 提取表当前定义为准**（材料写 10、《提取表规范》写 9 组，须现场核对） | 生成前必做第 8 条 |
| D15 | （提示级，不打回）Excel 格式：微软雅黑 10pt、表头 `#70AD47`、模块 / 子模块加粗、全边框、自动换行、冻结首行 | 第六步 |

> **已删除项**（和解移除，不再校验）：D6 预置条件固定文案、D7 用例级别 LV0~LV4 计数（LV 语义判定移交判官 R5）、D11 步骤数 ≤4 / 自动化 ≤6、D12 标题 = FTS 名称一致（按本仓库=二组口径删除）。

## 组归属假设（一处翻转点）

本层 D2、及判官题集里所有"二组机制"条件题，均按 **本仓库 = 二组（电表组）口径** 取舍——依据：本仓库确有 `bugs/INDEX.md`、`testcase/` 基线、跨项目同源模块、存量集成场景，正是被标"二组机制"的题所依赖的事实。

若此假设为误（本仓库实为一组），需翻转：恢复 D12，并复核 C6/C7/R8/R9/E5（用例）等"二组机制"条件题的取舍。
