# 脑图判官题集（测试策略脑图 / XMind）

> 评测对象 = `strategy-design` 生成的 XMind 测试策略脑图。上游 = **需求文档**（可独立触发，不要求下游用例已生成）。
> 由 `binary-eval-judge` 判官逐题盲评；计分/门槛/分批/投票见 `scoring-and-protocol.md`。
> 本题集为 0724 评审版**和解后版本**：`删除` 项已移除，`降级` 项已改维度，`存疑` 项标 `〔待定〕`，"二组机制"按 **本仓库=二组（电表组）口径** 取舍（翻转点见 `deterministic-checks.md`）。

| # | 评测问题 | 期望 | 类型 | 关联context | 规则依据 |
|---|----------|------|------|-------------|----------|

| C2 | 每个可输入非法值的数值字段，是否覆盖了全部强制非法等价类（超上界 / 超下界 / 负数 / 非数字字符 / 特殊符 / 空）？ | 是 | — | 否 | 方法学·强制非法等价类 |
| C3 | 〔条件题〕需求中有数值 / 长度范围的参数，是否都覆盖了边界有效值（最小 / 最大）与刚超界值？**纯 MCU 硬件层边界超出测试组能力的判 ⚪ 并举证** | 是 | — | 需求 | 方法学·边界值 |
| C4 | 每个开关 / 前置依赖，是否都有反向测试点（未启用时字段不可见 / 不可配置）？ | 是 | — | 需求 | 第四步 |
| C5 | 配置类 / 协议通信类功能，是否评估了异常恢复（断网重连、掉电 / 重启配置持久化）——有对应测试点**或显式说明不适用**？ | 是 | — | 否 | 方法学·默认必评项 |
| C6 | 知识库提取表「共存 / 联动约束」「历史缺陷模式」中列出的事实，是否存在未转化为测试点且未说明理由的遗漏？ | 否 | ⭐ | 知识库 | 生成前必做 |
| C7 | 每个主流程操作，是否同时覆盖了成功场景与失败 / 异常场景？ | 是 | — | 否 | 参考范本 Q4 |
| C8 | 涉及枚举 / 下拉字段的测试点，是否覆盖了需求 / feature_map 声明的**全部**合法选项值（而非抽样部分值）？ | 是 | ⭐ | 需求 | 枚举遍历完整性 |
| C9 | 对"被其他功能依赖"的功能，是否补了反向依赖测试点（本功能未配置时下游降级、本功能首次配置后下游变可用）？ | 是 | — | 知识库 | 反向依赖检索 |
| C10 | 〔集成模式条件题·待定〕test_baseline §一 标为高发缺陷的功能，是否标注 `[高风险]` 或明显上调了测试点密度（对比同类普通功能）？（加密程度口径待双组确认） | 是 | — | 知识库 | 风险加权 |
| C11 | 〔条件题·IP 双栈〕对**声明支持 IPv4/IPv6 双栈**的网关 / 云功能，是否覆盖双栈？上位机（纯 RTU）、AcuDC-320（仅 Modbus RTU）等无 IP 栈设备判 ⚪ | 是 | — | 需求 | 方法学·默认必评项（行业条件化） |
