# 计分公式、门槛与判官实施约定

> coverage-check ② 判官层的计分规则与判官调度约定。判官题集见 `judge-questions-strategy.md` / `judge-questions-cases.md`；确定性层见 `deterministic-checks.md`。

## 计分公式（材料值，固定）

**脑图**（strategy 产物）：
```
总分 = 100 × 35% × (完整性答对 / 完整性题数)
     + 100 × 35% × (正确性答对 / 正确性题数)
     + 100 × 10% × (一致性答对 / 一致性题数)
     + 100 × 20% × (可执行性答对 / 可执行性题数)
```

**用例**（cases 产物）：
```
总分 = 100 × 30% × (完整性答对 / 完整性题数)
     + 100 × 30% × (正确性答对 / 正确性题数)
     + 100 × 10% × (一致性答对 / 一致性题数)
     + 100 × 20% × (可执行性答对 / 可执行性题数)
     + 100 × 10% × (清晰性答对 / 清晰性题数)
```

**计分规则：**
- "答对" = 判官对该题的回答与题集中「期望答案」一致。
- 判 `⚪不适用` 的条件题**不计入对应维度分母**（避免"本就不适用"的题拉低得分）。
- 判 `无法判定`（提取表缺字段等）的题**不计入分母**，但在报告显式列出为"待补字段后重评"，不得当作 PASS。
- 红线题（X1/X3/X4）**独立于加权分**：任一答错即整体 FAIL、不再计加权分。

## 门槛

| 分数 | 结论 |
|------|------|
| ≥90 | 优秀 |
| 70–89 | 良好（可提交人工门禁） |
| <70 | 打回重生成 |

红线任一 FAIL → 整体 FAIL，无视加权分。

分数与逐题结果作为人工门禁的**预审报告**，**不替代人工签字**。

## 校准声明（必须写进报告头）

范围内**未建判官校准样本集**（材料要求接自动门禁前须用种子缺陷样本校准判官准确率 ≥85%）。因此报告头必须显式标注：

> 本分数为**预审建议**，未经判官校准（准确率未反标），**不替代人工签字**，仅供工程师参考是否回炉。

## 判官实施约定

1. **独立盲评 + 只读**：判官为 fresh-context 子智能体（`binary-eval-judge`），工具仅 Read/Grep/Glob；只见产物 + 按题需要的关联材料 + 题目，不见生成过程对话。只判定、只记问题，**不改产物、不出修复码**。

2. **按「关联context」分批组装上下文**（不硬编码题数，按题目 `关联context` 列聚类）：
   - `否`（仅产物）题：单独一批，只喂产物，成本最低；
   - `需求` 题：喂 产物 + 需求文档；
   - `知识库` 题：喂 产物 + 知识库提取表（及 bugs/INDEX.md / testcase 摘要）；
   - `需求+知识库` 题：两者同喂；
   - `脑图` 题（用例模式）：喂 产物 + 来源脑图；
   - `RN` 题：喂 产物 + release notes；
   - 红线 X3/X4 需 需求 + 知识库（型号清单 / 精度等级）同喂。

3. **四态判定**：`是` / `否` / `⚪不适用` / `无法判定`。
   - `⚪不适用`：仅题干标〔条件题〕〔集成模式条件题〕、且依赖材料确不存在或场景确未触发时可判；**必须引用需求 / 脑图 / 提取表的具体章节号或"不支持 / 不涉及"明确字样**，禁止凭常识 / 型号印象推断。
   - `无法判定`：提取表缺字段致无法比对时判此（**不判 ⚪ 静默放行**），报告列为"待补字段后重评"。

4. **红线判定优先**：红线题先于加权题判定，任一答错即 FAIL、不再计加权分。

5. **输出格式**：每题 `{题号, 回答, 判定依据引用（编号 + 原文）, 置信}`；主线程比对期望答案后出分。

6. **低置信 / 争议处理**：
   - **红线题与重点问题（⭐）若置信 <0.8** → 主线程并发派 **3 个判官投票取多数**，不因单次 LLM 判断直接 FAIL 流水线；
   - 其余普通题低置信 → 按单判官结果计分，报告标注"待核"。

7. **版本绑定**：题集引用的「SKILL 第 X 步 / 反例 N」随 strategy-design / testcase-design 迭代会漂移；规则变更时须同步复核题集，`〔待定〕` 项以生成 skill 当前实际定义为准。

## 主线程调度流程（判官层）

> **题集流向**：判官**不自读题集文件**。主线程读 `judge-questions-{strategy,cases}.md`、按 `关联context` 分批，把该批题目**内联**进派给判官的 prompt。判官是通用盲评引擎，喂什么答什么。
> **剥离期望答案**：内联给判官的题目**必须去掉「期望」列**，只留 `题号 / 评测问题 / 问题类型 / 关联context / 规则依据`。期望答案由主线程持有、事后比对——防止判官反推锚定。

1. 按 `关联context` 把该模式的题集聚类成若干批；**每题剥去期望答案列**。
2. 每批派一个 `binary-eval-judge`（Agent 工具，`subagent_type: binary-eval-judge`），传入 `{产物 + 该批关联材料 + 该批题目（无期望答案）}`。红线批优先。
3. 收齐各批 `{题号, 回答, 依据, 置信}`。
4. 对 置信<0.8 的红线题/⭐题，并发再派 3 判官投票，取多数覆盖原判。
5. 主线程比对期望答案 → 算各维度答对数/分母 → 套公式出维度分与总分。
6. 红线任一 FAIL → 标 FAIL。
7. 组装预审报告（格式见 SKILL.md 第五步）。
