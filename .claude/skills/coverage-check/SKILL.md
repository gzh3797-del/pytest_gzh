# coverage-check 二元性评测查漏复核 Skill

## 概述

**核心原则：两层评测 + 独立盲评判官 → 维度加权预审分 + 红线判定 + 三档分级漏点，仅对话输出。**

被检产物是同一上下文刚生成的，自检存在**自我背书偏差**。本 skill 把质量评估拆成一组**预设标准答案的是/否判定题**，由 fresh-context **盲评判官**逐题客观判定并举证，比对期望答案后按维度加权计分，把"漏没漏/对不对"变成可核对、可计分的条目。

评测分两层：
- **① 确定性自检层**（主线程内联解析，非 LLM）：机器能判的格式/结构/编号/泛称/黑词等，标 🔴 者命中直接打回；
- **② 判官题集层**（派 `binary-eval-judge` 盲评只读判官）：机器判不了的语义题，红线先判、其余按维度加权。

**本 skill 不生成任何文件，不回填 XMind / Excel。** 只在对话里给预审报告，由工程师决定是否回炉。判官与修复严格分离——判官只判定、不改产物。

## 输入约定

调用方传入：
- **原始需求文档路径**（最终权威基准）
- **刚生成的产物**（XMind 脑图 或 Excel 用例）
- **模式标识**：`脑图` 或 `用例`
- （用例模式）**来源脑图**路径
- （可选）**知识库提取表**（两个生成 skill 本就产出；缺失时判官对依赖它的题走"无法判定"并报缺）
- 知识库对照材料：项目 `bugs/INDEX.md` / `testcase/` 摘要 / `context.md`

## 异常与降级（if-then）

命中即按表处理，禁止静默跳过；凡走降级路径，必须在报告开头显式声明，让工程师知道本次评测可信度：

| 触发条件 | 一线处理 | 仍失败兜底 |
|----------|----------|------------|
| 输入必填项（需求路径/产物/模式）缺任一 | 向调用方索要 | 拿不到 → 终止，列出缺什么，不臆测 |
| `binary-eval-judge` 不可用（超时/环境限制） | 主线程自行盲评（"先不看生成过程"逐题判定），报告标注「降级：未用独立判官 agent，存在自我背书风险」 | 判官层整体不可行 → 只跑 ① 确定性层 + 需求可追溯回扫，结论降为参考级 |
| 产物解析失败（.xmind/.xlsx 损坏或格式异常） | 报出文件路径与错误点，请调用方重新生成 | 不猜测产物内容继续评测 |
| 知识库提取表缺失/缺字段 | 依赖它的题判官回「无法判定」，报告列为"待补字段后重评" | 不静默判 ⚪ 放行 |
| 无来源脑图（纯需求直转用例） | 跳过 用例 D13 与 `关联context=脑图` 的题，报告注明 | — |
| `context.md` 无设备清单 | 回退用 `CLAUDE.md` 支持设备速查表 | 两处都无 → 型号遍历红线 X3 判「无法判定」并说明 |
| `bugs/INDEX.md` / `testcase/` 缺失或为空 | 对应集成模式条件题判 ⚪ 并举证 | — |
| 无跨项目同源模块 | C7（用例）判 ⚪ 并说明 | — |

## 第一步：识别模式与基准链

| 模式 | 上游基准 | 题集 | 确定性层 |
|------|----------|------|----------|
| **脑图** | 需求文档 | `judge-questions-strategy.md` | 脑图 D1–D10 |
| **用例** | 来源脑图（无脑图则需求文档） | `judge-questions-cases.md` | 用例 D1–D15 |

## 第二步：① 确定性自检层（主线程内联，非 LLM）

按 `deterministic-checks.md` 对应清单，主线程内联解析产物核对（xlsx 用 openpyxl、xmind 用 zipfile + xml）：
- 标 🔴 的确定性红线命中 → **直接打回，不进 ② 判官层**，报告说明命中项；
- 非红线项不通过 → 记为缺陷，仍进 ② 层（不阻断）；
- 全部通过 → 进 ② 层。

> 无脑图的纯需求直转用例场景跳过 D13，报告注明。

## 第三步：② 判官题集层（派盲评判官）

> **题集不由判官自读**：主线程读 `references/judge-questions-*.md`、分批后把题目**内联**进判官 prompt；判官是通用盲评引擎。内联题目**须剥去「期望」列**（期望留主线程比对，防判官锚定）。

按 `scoring-and-protocol.md` 的「主线程调度流程」执行：
1. 按题目 `关联context` 把题集聚类成若干批（`否` / `需求` / `知识库` / `需求+知识库` / `脑图` / `RN`），每题剥去期望答案列。
2. 每批派一个 `binary-eval-judge`，传 `{产物 + 该批关联材料 + 该批题目（无期望）}`。**红线批优先**。
3. 收齐各批 `{题号, 回答, 依据引用, 置信}`。
4. **红线题 / ⭐重点题 置信 <0.8 → 并发再派 3 判官投票取多数**，覆盖原判。
5. 判官**只判定不打分、不改产物**；⚪/无法判定 按约定处理（缺字段报"待补"，不静默放行）。

## 第四步：计分

主线程按 `scoring-and-protocol.md` 计分：
- 比对判官回答与题集「期望答案」→ 各维度答对数 / 分母（⚪ 与 无法判定 不入分母）；
- 套公式算维度分与总分；
- 红线任一答错 → 整体 **FAIL**（不计加权分）；
- 门槛：≥90 优秀 / 70–89 良好 / <70 打回。

## 第五步：预审报告（仅对话）

**必须包含以下部分，不要自创格式：**

1. **报告头**：
   - 总分 + 门槛档位（优秀/良好/打回）
   - 红线 verdict：`PASS` 或 `FAIL`（FAIL 列出哪条红线、依据）
   - 是否走了降级路径（走了要显式声明）
   - **未校准声明**（原文见 `scoring-and-protocol.md`）：分数为预审建议、未经判官校准、不替代人工签字
2. **维度分表**：每维度 `答对/题数 → 得分`。
3. **逐题结果**：至少列出 **答错题 + 低置信题 + ⚪/无法判定题**，每条附判官的依据引用。
4. **🔴/🟡/🟢 三档漏点清单**（把判官答错题翻译成可读缺陷，兼容现有下游习惯）：
   - 🔴 **确认漏/错**：红线 FAIL、或需求/脑图明确有而产物没有/写错，附定位。
   - 🟡 **疑似漏（待确认）**：低置信题、⭐题存疑、条件题边界，需工程师判断。
   - 🟢 **已覆盖**：核对通过的关键维度，简列即可。
5. **结尾**：是否建议回炉、优先补哪几条。**不直接改产物。**

## 评测检查清单

🔴 **CHECKPOINT** · 输出前逐项确认：
- [ ] 已按模式选对题集与确定性清单
- [ ] ① 确定性层已内联解析核对；🔴 确定性红线命中已直接打回并说明
- [ ] ② 判官层按 `关联context` 分批派 `binary-eval-judge`，红线批优先
- [ ] 判官全程只读：未改产物、未采纳任何修复建议
- [ ] 红线题/⭐题 置信<0.8 已派 3 判官投票取多数
- [ ] ⚪不适用 均有章节举证；提取表缺字段的题按"无法判定+待补"处理，未静默放行
- [ ] 已按公式算维度分与总分；⚪ 与 无法判定 未计入分母
- [ ] 红线任一答错已标整体 FAIL
- [ ] 报告头含 总分/门槛/红线verdict/降级声明/未校准声明
- [ ] 逐题结果列全 答错+低置信+⚪/无法判定题，均附依据引用
- [ ] 三档漏点每条写明 定位 + 命中题号 + 建议
- [ ] 走了降级路径的已在报告开头声明
- [ ] 未生成任何文件、未改动 XMind/Excel

## 常见误区

| 误区 | 纠正 |
|------|------|
| 只肉眼扫产物觉得"挺全" | 必须派盲评判官逐题判定 + 举证，否则被既有答案锚定 |
| 判官顺手给"应改为 XXX"修复建议 | 判官只读只判定，评审与修复严格分离；修不修由工程师定 |
| 提取表缺字段的题判 ⚪ 放行 | 缺字段是"无法判定+响亮报缺"，不是不适用；静默 ⚪ = 假 PASS |
| 凭"这型号应该没 IP 栈"判 ⚪ | ⚪ 必须引提取表/需求具体章节，禁止常识臆测 |
| 单次 LLM 判断就 FAIL 流水线 | 红线/⭐题低置信须 3 判官投票，避免单判官误杀 |
| 把分数当门禁签字 | 未校准，分数仅预审建议，不替代人工 |
| 顺手把漏点补进 XMind/Excel | 本 skill 只给结论，回填与否由工程师决定 |
