# coverage-check 查漏复核 Skill

## 概述

**核心原则：独立重导 + 多基准回扫 → 三档分级结论，仅对话输出。**

被检产物是同一上下文刚生成的，自检存在**自我背书偏差**——会把"我生成的"默认当成"完整的"。本 skill 用一个**独立子智能体**先抛开产物重新推导一遍，再叠加四类基准回扫，把"漏没漏"变成可核对的条目。

**本 skill 不生成任何文件，不回填 XMind / Excel。** 只在对话里给结论，由工程师决定是否回炉。

## 输入约定

调用方传入三项：
- **原始需求文档路径**（脑图/用例的最终权威基准）
- **刚生成的产物**（XMind 脑图 或 Excel 用例）
- **模式标识**：`脑图` 或 `用例`

## 第一步：双模式识别基准

| 模式 | 基准链 |
|------|--------|
| **脑图** | 需求文档 ↔ 已生成脑图测试点 |
| **用例** | ① 用例 ↔ 脑图（拆分是否漏分支、标「X个用例」是否严格按数、含「待确认」是否正确跳过）② 用例 ↔ 需求（端到端是否漏需求点） |

## 第二步：独立重导（保证不自我背书）

**派一个独立子智能体（fresh context），先不看产物**，仅凭需求文档（用例模式再加脑图）独立重新推导一遍应有的测试点/用例，再与已生成产物做**差异比对**：独立推导有、产物没有 → 候选漏点。

> 子智能体须遵守 strategy-design / testcase-design 的「分析隔离原则」：从当前需求/脑图原始内容重新读取，不带历史记忆。

## 第三步：四类基准回扫

独立重导之外，逐项过下面四类基准（这几类是肉眼扫最容易系统性漏掉的）：

**1. 需求可追溯性** —— 需求文档每个需求点是否都映射到 ≥1 个测试点/用例。逐条对需求打勾，没映射的就是漏需求（含功能行为类需求，如"禁用后不响应"）。

**2. 方法学回扫**（对照 `knowledge/shared/test_design_methods.md`）：
- 该用**决策表**（≥2 条件组合）/ **状态转换**（启停、主备、连接生命周期）/ **正交**（多因素组合）而没用？
- 数值字段非法等价类是否**按字段类型全覆盖**：超上界 / 超下界 / 负数 / 非数字字符 / 特殊符 / 空——**不能只测"刚超界"一类**；
- **同类字段一致性铁律**：同类字段（如多个数值参数、多个 IP 字段）的非法等价类划分是否**一致**——A 字段测了负数/特殊符而同类 B 字段没测，是最常见漏测，必须点出。

**3. 清单回扫** —— 逐项核对被检 skill 自带的「生成检查清单」：
- 入口/启停/开关依赖**反向**（未启用时字段不可见/不可配）；
- 禁用后效果、多功能共存；
- **配置/通信类必评项**：异常恢复（断网重连 / 掉电·重启后配置持久化）、**IPv4/IPv6 双栈**——每个此类功能都要评估，漏了就提，不适用要显式说明；
- 用例模式另核：编号规则、用例级别 LV0~LV4、「X个用例」数量、「待确认」跳过、步骤/预期编号对应。

**4. 横向比对（已有业务/已有用例）**：
- 该项目 `bugs/INDEX.md` 历史缺陷模式——产物是否覆盖（防回归漏测）；
- `testcase/` 下**同类模块已有用例**——本次有没有漏掉对方测过的维度；
- 项目 `context.md` 跨模块联动、下挂设备/共存范围是否漏。
- 知识库为补充背景，与当前需求文档冲突时以当前文档为准。

## 第三步补充：「待确认」不计漏

被检产物中标题含「待确认」的节点/分组是**有意跳过**的，不算漏点，不纳入查漏。

## 第四步：三档分级输出（仅对话）

**必须用下面三档，不要自创格式。** 每条漏点写明：**漏在哪 + 命中哪个基准 + 建议补什么**。

- 🔴 **确认漏**：需求/脑图明确有、产物没有，附定位（哪个分组/模块）。
- 🟡 **疑似漏（待确认）**：由方法学 / 历史 bug / 同类用例推断可能漏，需工程师判断。
- 🟢 **已覆盖**：核对通过的关键维度，简列即可（证明查过，不展开）。

结尾一句：是否建议回炉补充、优先补哪几条。**不直接改产物。**

## 查漏检查清单

输出前逐项确认：
- [ ] 已按模式选对基准链（用例模式做了双层比对）
- [ ] 已独立重导并与产物差异比对（不是只肉眼扫产物）
- [ ] 需求每条都核了可追溯性，功能行为类需求未漏
- [ ] 数值字段非法等价类按字段类型全覆盖，且核了**同类字段一致性**
- [ ] 配置/通信类已核 异常恢复 + IPv4/IPv6 双栈，漏了已提或已说明不适用
- [ ] 已比对 bugs/INDEX.md 历史缺陷与 testcase/ 同类用例
- [ ] 含「待确认」节点未计入漏点
- [ ] 输出用 🔴/🟡/🟢 三档，每条写明定位+基准+建议
- [ ] 未生成任何文件、未改动 XMind/Excel

## 常见误区

| 误区 | 纠正 |
|------|------|
| 只肉眼扫产物觉得"挺全" | 必须独立重导再差异比对，否则被既有答案锚定 |
| 数值字段只提"还要测无效值" | 要按类型逐类枚举：超界/负数/非数字/特殊符/空 |
| 测了 A 字段非法类，没核同类 B | 同类字段划分必须一致，这是头号漏测来源 |
| 忘了 IPv4/IPv6 双栈、掉电持久化 | 配置/通信类默认必评，漏了要提或显式说明不适用 |
| 不看历史 bug / 同类用例 | 横向比对是"分析已有业务/已有用例"的核心，不可省 |
| 顺手把漏点补进 XMind/Excel | 本 skill 只给结论，回填与否由工程师决定 |
