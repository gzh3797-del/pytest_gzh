# 测试模块迁移 Skill

## 概述

本 skill 定义把测试模块代码从**源工程**（常是 Downloads 快照或他人工程）迁移到**目标工程**（如 `autotest/projects/AcuHMI_1_7`）的标准流程。

**最高优先级：迁移后代码必须能跑通。** 其次才是合并正确、结构适配。

**核心风险（务必牢记）：** 目标工程可能已被他人迁移过并继续开发，源码往往是**旧快照**。盲目复制会：
- 用旧代码覆盖更新的版本
- 丢失目标独有的用例
- 回退已经适配好的路径/配置

这直接违反"迁移后必须能跑通"这条最高准则。**所以第一步永远是 diff，而不是复制。**

---

## 迁移四步（每次必须按序执行）

### 第 1 步：先 diff，再动手（防回退守则）

1. 清除两侧的噪声目录后再比对，避免无关差异干扰判断：
   `allure-results/`、`__pycache__/`、`.pytest_cache/`、`reports/`
2. 逐文件比对**源**与**目标**，判定谁是**超集**：
   - 若**目标严格更大**且**源无独有内容** → 目标已是更新版本，**不要覆盖**，向用户确认后再决定（覆盖已有/更新文件属"需确认"场景）。
   - 若**源含有目标缺失的内容** → 进入第 2 步做合并。
   - 若目标目录不存在 → 全新迁移，直接进入第 2 步。

> 判定超集是防回退的关键。宁可多问一句，也不要用旧快照盖掉别人已适配的版本。

### 第 2 步：合并（只补缺，不覆盖）

- 目标已有代码时，**只把源中"目标缺失"的片段并入**。
- 相同或更旧的内容**不动**。
- 全新迁移时才整体拷入。

### 第 3 步：结构适配

- **模块目录**：要有本模块的 `README`（说明用途/执行方式）+ 个性化 `config.yaml`。
- **项目根 README**：新增本模块的执行命令，并补一行模块索引。
- **依赖迁移**：源模块依赖的所有 `config/helpers/pages/...` 迁到目标的公共目录；目标已有则合并，不重复。

### 第 4 步：冒烟校验

```bash
python -m pytest <目标模块路径> --collect-only -q
```

判定"跑通"的标准：**0 收集错误、无导入路径断裂**。有报错就回到对应步骤修正导入/路径/配置，直到收集干净。

## 快速参考

| 事项 | 做法 |
|------|------|
| 典型源路径 | Downloads 快照，如 `...\AcuHMI-1-7\tests\<module>` |
| 典型目标路径 | `autotest\projects\AcuHMI_1_7\tests\<module>` |
| diff 前先清 | `allure-results` / `__pycache__` / `.pytest_cache` / `reports` |
| 超集判定 | 目标更大且源无独有 → 别覆盖，先问 |
| 冒烟命令 | `python -m pytest <模块路径> --collect-only -q` |
| 优先级 | 能跑通 > 合并正确 > 结构适配 |
| 中间脚本 | 写入 `%TEMP%`，不得留在工作目录 |

---

## 常见错误

- **直接复制覆盖** —— 没先 diff 判超集，用旧快照回退了别人已适配的版本。永远先 diff。
- **只搬模块、漏搬依赖** —— 模块能收集但导入报错。第 3 步把 `config/helpers/pages` 一并迁移/合并。
- **忘了结构适配** —— 模块目录缺 README/config.yaml，或项目根 README 没登记本模块执行命令。
- **没做冒烟就宣布完成** —— 必须跑 `--collect-only -q` 看到 0 错误才算跑通。
- **中间脚本留在工作目录** —— 迁移过程用到的临时 Python 脚本一律写 `%TEMP%`，工作目录只保留最终代码与产物。

## 🔴 CHECKPOINT：何时向用户确认

按用户既定习惯：**直接执行，无需确认**；仅以下情况**命中即 🛑 STOP，先向用户确认再动手**：
- 目标是超集、需要覆盖已有/更新文件时（防回退）。
- 判定为**跨不同项目**（非同一产品/环境）迁移，规则可能不同时。
