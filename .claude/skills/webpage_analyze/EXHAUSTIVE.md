# 穷尽式页面探索规范

## 目标
确保AI遍历页面所有角落，不漏掉任何隐藏内容、弹框、下拉、滚动区、动态加载内容。

## 核心原则

> **交互即探索** — 每遇到一个可交互元素，先触发它看看会发生什么，再继续前进。
> **"看不到不代表没有"** — 页面中凡是能折叠、能滚动、能点击展开的区域，都必须主动打开查看。

---

## 一、视口与滚动规范

### 1.1 全页滚动扫描
- 将页面**滚动到底部**，确保所有懒加载内容被触发
- 将页面**滚动到顶部**，回到初始状态
- 对每个超过视口高度的区域，逐屏滚动扫描

```
browser_evaluate --function "() => window.scrollTo(0, document.body.scrollHeight)"
browser_wait_for --time 2
browser_evaluate --function "() => window.scrollTo(0, 0)"
```

### 1.2 局部滚动容器
- 识别所有 `overflow: auto | scroll` 的容器（如表格体、消息列表）
- **逐个滚动到这些容器的最底部**，观察是否有动态加载
- 记录每个滚动容器的内容总量与可见量的差异

### 1.3 固定/悬浮元素
- 检查页面四角是否有固定定位（fixed/sticky）的元素
- 包括：悬浮客服、回到顶部、Cookie 同意横幅、悬浮菜单
- 这些元素可能遮挡下方内容，也需要记录

---

## 二、显式交互触发规范

### 2.1 所有可点击元素（按钮、链接、图标）
- 对于页面上**每个 button、a、role=button** 元素，判断其行为类型：

| 行为类型 | 判断依据 | 处理方式 |
|----------|----------|----------|
| 打开弹框 | 点击后出现新层 | 记录弹框内容后关闭 |
| 展开/折叠 | 点击后内容展开 | 展开后捕获，再折叠 |
| 跳转页面（外域） | 链接到外部域名 | 记录目标 URL，不自动跳转 |
| 跳转页面（同域） | 链接到同域子页面 | **必须点击进入，对子页面执行完整探索，记录后返回** |
| 提交表单 | 表单提交 | 记录提交行为，但不实际提交（除非明确标记为非破坏性） |
| 无副作用 | 纯UI切换（如tab） | 全部触发一遍 |

**同域判断标准**：
- 同域 = 协议+域名相同（如 `https://sahitest.com/demo/` 下的所有 `.htm`/`.html`/`.php` 链接）
- 相对路径链接（`linkTest.htm`、`/demo/php/upload.htm`）→ 同域，必须跟随
- 绝对同域链接（`https://sahitest.com/demo/xxx.htm`）→ 同域，必须跟随
- 外部域（`https://google.com`、`https://sahitest1.com`）→ 外域，仅记录 URL
- JS 伪协议（`javascript:...`）→ 不导航，仅记录行为

### 2.2 下拉选择框（select / 自定义下拉）
- **必须打开每个下拉框**，列出所有选项
- 对于自定义下拉（非原生 select），找到触发元素并点击展开
- 记录每个选项的文本和值

```
# 先尝试原生select
browser_select_option --target "select[name='country']" --values "['option1']"
browser_snapshot --filename "dropdown_country_state1.md"

# 再依次选择其他选项，观察页面变化
```

### 2.3 折叠面板 / 手风琴（Accordion）
- 页面上所有带展开/折叠能力的面板**逐个展开**
- 记录每个折叠面板的标题和内容
- 注意嵌套折叠（折叠内还有折叠）

### 2.4 标签页（Tabs）
- 点击**每一个 tab 标签**，切换到对应面板
- 对每个 tab 面板内部，**递归执行本规范的全部探索步骤**

### 2.5 悬停触发的浮层（Hover/Flyout）
- 识别所有悬停才显示的下拉菜单、tooltip、浮层
- 使用 `browser_hover` 触发它们
- 捕获浮层内容后移走鼠标

```
browser_hover --target "nav-item-1"
browser_snapshot --filename "hover_menu_nav1.md"
```

### 2.6 分页 / 加载更多
- 如果页面有分页器，点击**每一页**查看内容
- 如果有"加载更多"按钮，**持续点击直到所有内容加载完毕**
- 记录总数据量和分页策略

---

## 三、弹框与浮层规范

### 3.1 弹框（Modal/Dialog/Alert）
- 对所有能触发弹框的元素，逐个触发
- 弹框打开后：
  1. 截取弹框的结构（`browser_snapshot`）
  2. 检查弹框内部是否有交互元素 → 递归探索
  3. 检查弹框后的背景是否有变化（遮罩层）
  4. 关闭弹框（点击关闭按钮或取消）

### 3.2 侧边栏抽屉（Drawer）
- 所有从边缘滑出的面板（左/右/上/下），全部触发打开
- 检查抽屉内的滚动内容

### 3.3 气泡/下拉菜单（Popover/Dropdown）
- 识别所有点击触发的弹出层
- 打开→捕获结构→关闭

### 3.4 Toast / 通知
- 注意短暂出现的提示消息
- 有些 toast 是触发操作后才出现，需在操作后立即捕获

---

## 四、表单深度探索规范

### 4.1 输入字段
- 对每个 input/textarea，记录类型、限制、占位符
- **点击每个字段**，观察是否触发日历/拾色器/建议列表

### 4.2 单选/多选组
- 对于 radio group：**每个选项都选中一次**，观察页面变化
- 对于 checkbox：分别测试选中和未选中状态

### 4.3 级联选择
- 识别联动下拉（如省/市/区）
- 选择一级选项后，等待二级选项加载，再打开二级下拉
- 逐级展开直到最末级

### 4.4 文件上传
- 点击上传按钮，记录支持的文件类型提示
- 注意拖拽上传区域

### 4.5 自动补全/搜索建议
- 在搜索框中输入文字，**等待建议列表出现**
- 记录建议列表的结构

---

## 五、动态内容规范

### 5.1 条件显示
- 页面中可能包含基于状态显示/隐藏的内容
- 切换不同选项，观察哪些区域出现/消失
- 记录显示条件规则（如 "仅当选中XX时显示"）

### 5.2 异步加载（AJAX）
- 识别加载中的占位符（skeleton / spinner）
- 等待加载完成后捕获内容
- 查看 `browser_network_requests` 了解 API 接口

### 5.3 无限滚动
- 持续滚动到页面底部，**直到没有新内容加载**
- 记录总加载次数和数据量

### 5.4 定时刷新
- 注意页面上是否有实时更新的内容（如计数器、K线图）
- 等待一段时间后再次截图，对比变化

---

## 六、多页面与导航规范

### 6.1 页面类型判定与模式切换

在阶段4（最终确认）中，必须先判定页面类型，再决定后续探索策略：

| 页面类型 | 判定条件 | 探索模式 |
|----------|---------|---------|
| **表单页** | 含表单元素 >= 1 | 单页深度模式：对所有表单字段穷尽探索 |
| **列表/表格页** | 含 table/list 为主，含分页/搜索 | 单页遍历模式：翻页到最后一页 |
| **枢纽导航页** | 链接数 > 20 且 表单+弹框+下拉框 < 5 | **深度递归模式**：点击每个同域内部链接，进入子页面完整探索 |
| **混合页** | 链接数 > 20 且 表单+弹框 >= 5 | 单页优先 + 链接全量模式：主页面完整探索 + 子页面全量遍历 |

### 6.2 枢纽页递归探索流程

```
1. 统计所有同域内部链接，建立「子页面链接清单」
2. 按优先级排序优先探索：表单类 > 对话框类 > 交互类 > 结构类
3. 对每个子页面：
   a. 点击链接进入（或 browser_navigate）
   b. 等待页面加载完成
   c. 在子页面执行 EXHAUSTIVE.md 规定的全部探索步骤（滚动/展开/触发/遍历）
   d. **产出该子页 `_context.md`**（URL/标题/交互元素/状态分支/实测情报，格式见 OUTPUT_STANDARD.md）
   e. 返回索引页 → 继续下一个
4. **默认全量遍历**：所有同域子页面一个不漏，逐一进入完整探索。仅当用户明确指令抽样或子页面>100且用户同意时才降级。
```

> **产物映射**：每个可路由子页 → 一份 `<Prefix_SubPage>_context.md`（结构一致仅编号不同的子页代表性合并为一份）；遍历完成后维护 `_INDEX_context.md`。

### 6.3 面包屑
- 记录面包屑路径，理解当前页面在站点中的位置
- 对于枢纽页，记录从索引页到子页面的导航路径

### 6.4 历史状态
- 注意到浏览器历史的变化（SPA 路由）
- 如果页面使用 hash 路由或 history API，记录所有可能的路由状态
- 递归探索子页面时，注意管理浏览器历史栈（使用 browser_navigate_back 返回）

## 七、CSS 隐藏内容规范

### 7.1 显示/隐藏切换
- 通过 `browser_evaluate` 检查页面中所有 `display:none`、`visibility:hidden`、`opacity:0` 的元素
- 判断哪些是真正无关的（模板残留），哪些是可以通过交互显示的

```
browser_evaluate --function "() => document.querySelectorAll('[style*=\"display:none\"], [style*=\"visibility:hidden\"], [hidden]').length"
```

### 7.2 响应式隐藏
- 如果页面有响应式设计，不同屏幕尺寸显示不同内容
- 可考虑调整视口大小后再分析

### 7.3 无障碍隐藏
- 检查 `aria-hidden` 元素
- 区分哪些是辅助技术隐藏、哪些是内容隐藏

## 八、完成度检查清单

分析完成后，必须逐项确认以下内容已覆盖：

```
[ ] 页面已滚动到底部，懒加载已触发
[ ] 所有滚动容器已滚动到底
[ ] 所有折叠/手风琴已展开
[ ] 所有标签页已切换
[ ] 所有下拉框已展开并列出选项
[ ] 所有弹框/抽屉/浮层已触发并记录
[ ] 所有 hover 菜单已展开
[ ] 所有表单互斥选项已尝试
[ ] 分页/加载更多已遍历
[ ] 悬停元素已触发
[ ] 条件显示内容已触发
[ ] 搜索/建议已测试
[ ] 同域子页面已逐个探索（枢纽页必做，非枢纽页标注 N/A）
```

**如果任何一项未能执行，必须在 `_INDEX_context.md`「局限与未尽项」中说明原因。**

---

## 九、局限记录规范

对于无法探索的内容，必须记录：
1. **哪个元素/区域**未能探索
2. **未能探索的原因**（如：需要登录、需要特定权限、会造成数据变更）
3. **建议的探索方式**（如：提供测试账号后可深入）
