# 测试用例 Excel Skill

## 概述

本 skill 将测试点/脑图转化为可直接执行的 Excel 测试用例，格式严格对齐 AC-HMI 测试用例规范 v2.4。

**适用场景：** 任意项目，从脑图测试点、需求文档、测试策略生成标准 Excel 用例表。

**执行顺序（每次必须按序执行）：**
1. 阅读本文档第一步至第六步的全部规范
2. 阅读共享方法学文档 `knowledge/shared/test_design_methods.md`（方法分类与领域场景库），用于第五步的拆分判断
3. 按下方「生成前必做：读取当前项目知识库背景」章节确定目标项目，读取其 `context.md`，扫 `requirements/summaries/` 清单、`testcase/` 用例摘要（编号衔接+去重）与 `bugs/INDEX.md`，并**输出「知识库提取表」**（起草前必做）
4. 阅读下方「用例内容规范与拆分示例」章节
5. 起草用例内容，逐条核对检查清单
6. 阅读下方「Excel 文件生成规范」章节，生成 .xlsx 文件并提供下载
7. **生成文件后自动调用 `coverage-check` skill 做查漏复核**：传入「原始需求文档路径 + 刚生成的 Excel 产物 +（若有）来源脑图 + 模式标识`用例`」，由其独立重导并多基准回扫（用例↔脑图、用例↔需求双层比对），在对话里给三档分级查漏结论；本步不生成文件、不改动用例表，漏点是否回炉由工程师决定

---

## 分析隔离原则（每次必须遵守）

**每次处理新模块时，必须重新读取当前文档原始内容，严禁携带历史分析信息。**

- 每次为特定模块生成用例前，**必须从当前测试策略/需求文档重新读取该模块的原始内容**，不得依赖对话记忆中的旧版内容
- **严禁**将本次对话中对其他模块的分析结论带入当前任务
- **严禁**引用历史对话中对同一功能的旧版分析（需求或测试点可能已更新）
- 若当前读取内容与历史记忆存在任何不一致，**以当前读取内容为唯一依据**，不做融合
- **知识库是补充背景，不是权威来源**：项目 `context.md` / `requirements/summaries/` / `bugs/INDEX.md` / `testcase/` 摘要仅用于术语与模块/设备范围对齐、保证设备/共存覆盖完整、编号衔接与去重、历史缺陷场景借鉴；待测内容仍以会话喂入的当前测试策略/需求文档为唯一权威依据，**知识库与当前文档冲突时一律以当前文档为准**（知识库可能过时）。唯一例外：**已有用例的编号区间以 `testcase/` 中的用例表为权威**，新增编号必须避让

## 生成前必做：读取当前项目知识库背景

起草用例前，先定位当前项目并读取其知识库背景，避免漏掉项目级的跨模块联动、设备兼容/共存用例。

**1. 确定目标项目**
- 从测试策略/需求文档路径、输出路径或会话上下文推断当前项目，对照 `CLAUDE.md`「项目一览」表校对
- 推断不出或有歧义时，**反问用户确认，不臆测**

**2. 读取 `context.md`**
- 路径取自「项目一览」表的「详情」列（如 `knowledge/gateway/AcuRev4100WEB2/context.md`、`knowledge/cloud/context.md`）
- 用途：掌握现有模块结构、项目约定、下挂设备清单，保证模块/设备命名与覆盖范围和项目一致
- **提取设备清单（必做）**：把项目的被测/下挂设备具体型号清单（如 AcuRev4100、AcuIOM-01~04）摘出备用；用例步骤/预期凡涉及设备必须落到具体型号（硬性规则见「核心内容原则」第 5 条）
- **优先读「测试设计必读（固定结构速查区）」**：context.md 若含此区块（八字段固定表），「知识库提取表」直接以它为权威来源逐字段对应提取，正文只作补充；该区块缺失的老项目才回退为通读正文提取

**3. 扫 `requirements/summaries/` 清单，按需读相关摘要**
- 列出该项目 `requirements/summaries/` 目录下的文件清单（无 INDEX，按文件名判断相关性）
- 挑出与当前功能相关的摘要按需读取，用于保证跨模块联动、功能共存、设备兼容类用例不漏；**不全读**

**4. 扫 `testcase/` 用例摘要（编号衔接 + 去重）**
- 路径：项目知识库根（即 `context.md` 所在目录）下 `testcase/` 内的摘要 `.md`；摘要不含编号区间时，再按需打开对应 xlsx 只读「用例编号」列
- 用途一（编号衔接）：确认同模块已有用例的编号区间，新增用例编号从已有最大序号续接，**禁止与已有编号重复**（编号是全工程唯一主键，见「用例编号一一对应」约定）
- 用途二（去重）：已有用例已覆盖的场景不重复生成；确属增量但场景相近的，在「备注」列注明与已有用例的关系

**5. 读 `bugs/INDEX.md`（历史缺陷场景）**
- 路径：项目知识库根下 `bugs/INDEX.md`；只读精简索引，不翻 `bugs/raw/` 原件
- 用途：与当前功能相关的已知 bug 场景补为回归用例（通常 LV2/LV3），「问题单来源」列填对应 bug ID

**6. 跨项目同模块基线（同源模块先覆盖、再添加）**
- 触发条件：对照 `CLAUDE.md`「项目一览」，其他项目存在同名/同源模块（如 BACnet/IP、SNMP、AWS IoT、Wiring Check 在 web2 / hmi1-7 / RPP 间同源）；无同源模块则跳过本步并说明
- 定位：其他项目知识库根 `testcase/` 的摘要（必要时读用例表），提取该模块的**用例覆盖维度清单**作为基线
- 用法——先覆盖基线，再补本项目增量（超集思想，防止比老项目测得还少）：
  - 基线逐条三分类：`适用`（纳入本次生成，参数/设备/端口按本项目必读区与当前需求**适配后重写**）/ `不适用`（本项目无此功能/设备/规格不同，记入"不适用清单"并写原因）/ `待确认`（列出交人工审核裁决）
  - 输出「基线覆盖比对」：基线维度 ↔ 本次用例的对应关系，适用维度必须全覆盖
- 硬约束：**编号一律按本项目前缀重新生成，禁止照搬他项目编号**；参数值/设备型号/端口一律以本项目为准，禁止原样照抄；**当前需求文档仍是唯一权威**——基线只用于补维度查漏，需求中不存在的功能不得因基线而生成用例

**7. 兜底**
- 该项目无 `context.md`，或 `requirements/summaries/`、`testcase/`、`bugs/INDEX.md` 为空/不存在时，对应项跳过并一句话说明，照常用会话喂入的文档生成

**8. 输出「知识库提取表」（起草前必做，不得跳过）**

完成上述读取后、起草任何用例之前，必须在对话中输出下表，把"读到了什么"显性化为可核对的中间产物：

| 类别 | 提取到的事实（枚举写全，不得用"等"） |
|------|--------------------------------------|
| 设备清单 | 具体型号 + 数量/上限（如 AcuRev4100 ×3、AcuIOM-01~04 ×8） |
| 协议与端口 | 北向/南向协议、端口、功能码 |
| 模块结构与页面入口 | 与当前功能相关的模块、页面路径 |
| 共存/联动约束 | 跨模块联动、功能互斥/依赖 |
| 容差与比对约定 | 数值比对容差等项目约定 |
| 已有用例编号区间 | testcase/ 中同模块已占用的编号区间（新编号续接依据） |
| 已有用例覆盖 | testcase/ 摘要中同模块已覆盖范围（去重依据） |
| 历史缺陷模式 | bugs/INDEX.md 中与当前功能相关的 bug（回归用例来源，含 bug ID） |
| 相关历史需求 | summaries 中读取过的相关摘要及要点 |
| 跨项目同模块基线 | 他项目同源模块的用例覆盖维度（来源项目/文件名 + 三分类判定结果；无同源模块写"无"） |

**规则：**
- 每个类别必填；确无内容写 `无`，不得留空、不得省略行——空行即宣告"该维度我没读"，逼出漏读
- 表中事实必须给出来源（context.md / INDEX.md / 摘要或用例表文件名）
- 后续生成的用例凡涉及表中类别，必须与表中事实一致（设备落型号、编号从区间续接、回归用例填 bug ID）
- 🔴 **CHECKPOINT（工作流 gate）**：提取表随用例产物一起交人工审核，供审核人核对"读全了没有"

> 知识库的角色见上方「分析隔离原则」最后一条：仅作背景补充，与当前文档冲突时以当前文档为准。

## 第一步：列定义与顺序

Excel 列按以下顺序输出，**不得调整顺序、不得增减列**：

| 列名 | 说明 |
|------|------|
| 模块 | 一级功能模块名称，**加粗** |
| 子模块 | 二级功能模块名称，**加粗** |
| FTS编号 | 格式见编号规则 |
| FTS名称(用例编号) | 简短描述，与用例标题保持一致 |
| 用例编号 | 格式见编号规则 |
| 用例标题 | 简短中文标题，与 FTS名称 保持一致 |
| 预置条件 | 固定文案（见下） |
| 测试步骤 | 多行编号，步骤数量不限 |
| 预期结果 | 多行编号，与步骤对应 |
| 用例级别 | LV0~LV4 |
| 测试结果 | 默认留空 |
| 测试负责人 | 默认留空 |
| 备注 | 默认留空（判「否」时在此写明判否原因，见第四步补充） |
| 是否能自动化 | 能自动化标「是」，不能标「否」；判否原因写入「备注」列。见第四步补充 |
| 完成自动化 | 默认留空 |
| 问题单来源 | 默认留空 |

## 第二步：编号规则

**项目缩写生成规则：**
- 从项目名称中提取英文和数字核心标识
- 去掉空格、连字符、下划线等分隔符后转大写
- 示例：`AcuRev-4100-WEB2` → `ACUREV4100WEB2`，`AC-HMI` → `ACHMI`
- **不得固定写死为 ACHMI 或任何历史项目代号**

**编号格式：**
```
用例编号：TestCase_<项目缩写>_<一级模块3位>_<二级模块3位>_<用例3位>
FTS编号：FTS_<项目缩写>_<一级模块3位>_<二级模块3位>_<用例3位>
```
FTS编号 = 用例编号将前缀 `TestCase_` 替换为 `FTS_`，其余完全一致。

**编号冲突检查（必做）：** 生成前对照「生成前必做」第 4 步扫到的已有用例编号区间，同模块新增用例从已有最大序号续接；生成后全表自查无编号重复、且不与已有用例表任何编号冲突。

## 第三步：固定规则

- **预置条件**：统一固定写为 `设备已正常上电，相关服务正常启动`，不展开
- **测试步骤**：按 `1. 2. 3.` 多行编写，步骤数量不限
- **预期结果**：尽量与步骤逐条对应，按 `1. 2. 3.` 多行编写；可跳号但不得与步骤错位
- **FTS名称 / 用例标题**：保持简短，详细列表写入步骤和预期结果，不堆在标题里

---

## 第四步：用例级别（LV0~LV4）

| 级别 | 定义 |
|------|------|
| LV0 | 功能级冒烟。每个功能模块核心正向主流程的最小闭环，验证功能基本可用，可直接给开发自测。每个功能模块 1~2 条 |
| LV1 | 完整正向验证。合法参数配置（含有效边界值）、完整正向路径、关键配置生效与结果验证 |
| LV2 | 异常与非法输入。非法值、超出范围值、空值、错误提示、失败处理、关键异常恢复场景 |
| LV3 | 补充验证。兼容性、模式切换、次高频流程、联动规则、多功能共存、非主路径交互 |
| LV4 | 低优先级补充。信息展示完整性、低频细项、UI 细节、长稳或非阻塞问题 |

**分配原则：**
- LV0 只覆盖"能进入页面 + 完成一次核心操作 + 结果正确"的最小路径，每个功能模块严格控制在 1~2 条
- LV1 覆盖合法边界值（最小值、最大值）和完整正向路径，有效值配置成功属于 LV1
- LV2 覆盖非法值和异常场景，无效边界值（超出范围、空值）归 LV2，不归 LV1
- LV3、LV4 覆盖兼容性、低频路径、展示类细节，不影响核心功能可用性
- 只读信息展示、低频路径、长稳测试归 LV4，不标 LV0

## 第四步补充：「是否能自动化」判断

每条用例必须在「是否能自动化」列填 `是` 或 `否`，**默认先判断能否自动化：判不能则标「否」并在「备注」列写明原因，其余标「是」**。

**判定口径（基于当前自动化能力）：**

| 倾向「是」（可自动化） | 倾向「否」（难自动化） |
|------------------------|------------------------|
| 配置经协议/接口可写、结果可程序断言（读值比对、连接成功/失败、保存生效、报错码） | 仅靠桌面客户端/HMI 的 UI 可选项或显示的人工目视校验 |
| 数值/参数边界、开关启停、协议读写、只读约束验证 | 需多台实物设备组网、专用上位机工具（如 Niagara）人工操作 |
| 可脚本化的遍历、周期性稳定性读取 | 闪退/死机/外观等需人工观察的现象；需协议分析仪/示波器测时延的物理测量 |

**规则：**
- 标「否」时，「备注」列必须写一句判否原因（如「需 Niagara + 多台实表」「需协议分析仪测时延」「桌面端 UI 目视校验」）。
- 拿不准时，按"当前是否有可程序断言的手段"判断；无可靠断言手段则标「否」。
- **标「是」的用例，测试步骤必须满足「自动化用例步骤增强规范」（见"步骤与预期结果写法规范"章节）**——步骤是后续"用例转自动化脚本"的唯一信息源，写不到位等于自动化落不了地。

## 第五步：用例拆分原则

- 结合「生成前必做」读取的项目 `context.md` / 相关摘要，确保设备型号、下挂设备、跨模块联动等覆盖与项目一致，不漏项目级共存/兼容用例（与当前测试策略/需求文档冲突时以当前文档为准）
- **脑图一个最小分支 ≠ 一个用例**，应按校验维度、边界值、正/异常场景拆分
- 若脑图分支末尾标有「X个用例」，**必须严格按该数量生成**，不得增减
- 参数范围类测试点，自动按等价类/边界值生成：1 组有效值 + 无效值组按字段类型覆盖全部非法等价类（数值字段含 超界/负数/非数字/特殊符/空，见方法学文档清单），同类字段划分一致
- 涉及 IP / Subnet Mask / Gateway / DNS1 / DNS2 等常见参数，补充可执行的具体测试值

### 按测试方法拆分（对照共享方法学文档）

脑图测试点若由特定方法推导（见 `knowledge/shared/test_design_methods.md` 第一节），按该方法的产出粒度拆用例：

- **决策表类**（如 Wiring Check、分级/折扣、报警组合）：每条有意义的条件组合（规则）拆为 1 条用例，测试步骤写明该规则下各条件的具体取值，预期写明对应动作
- **状态转换类**（如 主备切换、连接断开→重连→在线、SSL 启停联动）：每条状态迁移拆为 1 条用例，并为关键非法迁移补 1 条异常用例（LV2/LV3）
- **正交 / pairwise 类**（如 多协议 × 多型号 × 多参数 兼容性）：按脑图给出的压缩后组合数生成用例，不自行展开为全组合；脑图未标数量时按正交表代表性组合生成并在备注说明压缩依据

## 第五步补充：「待确认」主题跳过规则

遍历 XMind 所有主题时，若某节点标题包含**「待确认」**（任意位置、任意大小写），处理规则如下：

- **该节点及其所有子节点**全部跳过，不生成任何测试用例
- 跳过范围：分支主题、细分主题、叶子节点，只要标题含「待确认」即跳过整棵子树
- 不在 Excel 中留占位行，不计入用例总数
- 若整个二级分组标题含「待确认」，该分组下所有用例均跳过

> **示例：** XMind 中存在节点 `Meter Point Configuration 待确认`，则该节点及其下全部子节点均不输出用例。

## 第六步：生成 Excel 文件

参考下方「Excel 文件生成规范」章节。

**格式规范摘要：**
- 字体：微软雅黑，10pt，全表统一
- 表头行填充色：绿色 个性色6（RGB `#70AD47`）
- 模块、子模块列内容：**加粗**

# 用例内容规范与拆分示例

## 核心内容原则

1. **完整可执行**：执行人员只看用例即可完成测试，不得再依赖脑图或需求文档
2. **列表完整写出**：脑图已列出的菜单、页面项、参数、字段、状态列表，用例中必须完整体现，不得用"等""相关项目""完整显示"代替
3. **标题简短，细节入步骤**：FTS名称/用例标题只写简要描述，详细列表写进测试步骤和预期结果
4. **步骤简洁但信息完整**：单条步骤一句话、不写大段，但每步必须带**具体操作对象和具体值**（完整菜单路径、参数全名、实际测试值），"简洁"指不啰嗦，不是省信息。一般用例不超过4步，超过则拆分；**标「是」（可自动化）的用例允许至6步**，以容纳"配置→保存→回读验证→还原"完整闭环，不得为凑步数省略回读或还原
5. **设备型号具体化（硬性）**：凡涉及被测/下挂设备的用例，步骤与预期必须写具体型号（对照「生成前必做」提取的 `context.md` 设备清单，如 AcuRev4100、AcuIOM-01），**禁止"设备""下挂设备""电表"等泛称**。脑图已写具体型号的，用例不得退化为泛称；脑图本身是泛称的，生成用例时按设备清单落到型号并在「备注」列注明；确与型号无关的用例，步骤中写明"任一型号"并给理由

---

## 拆分规则详解

### 规则1：按校验维度拆分
一个脑图分支同时包含多个独立校验维度时，拆成多个用例。

**示例：**
- 脑图：`查看4100参数：单位、精度、取值范围与上位机一致`
- 拆分为：
  - 用例1：对比参数**单位**与上位机一致
  - 用例2：对比参数**精度**与上位机一致
  - 用例3：对比参数**取值范围**与上位机一致

---

### 规则2：按边界值拆分（等价类+边界值分析）
测试点包含明确参数范围时，自动拆出至少2组：

| 组别 | 取值策略 |
|------|----------|
| 有效值组 | 边界内合法值，优先取边界值（最小值、最大值）和典型中间值 |
| 无效值组 | 按字段类型取**全部非法等价类**（见方法学文档「按字段类型的强制非法等价类」）：数值字段 = 刚超下界 / 刚超上界 / 负数 / 非数字字符 / 特殊符 / 空，**不得只取"刚超界"一类**；同类字段划分须一致 |

**示例1：**
- 脑图：`配置 Nominal Voltage: 1~690`
- 拆分为：
  - 用例1（有效值）：配置 Nominal Voltage = 1、500、690，保存成功
  - 用例2（无效值）：配置 Nominal Voltage = 0、691（超界）、-1（负数）、abc（非数字）、@（特殊符）、空，阻止保存并提示

**示例2：**
- 脑图：`Advertised APDU Timeout 默认3秒，范围3~60`
- 拆分为：
  - 用例1（有效值）：配置 Advertised APDU Timeout = 3s、60s，保存成功
  - 用例2（无效值）：配置 Advertised APDU Timeout = 2s、61s（超界）、-1（负数）、abc（非数字）、@（特殊符）、空，阻止保存并提示

---

### 规则3：参数遍历拆分
涉及多个同类参数遍历时，按参数逐条拆分，并补充具体可执行测试值。

**示例：**
- 脑图：`遍历配置Ethernet1：IP、Subnet Mask、Gateway、DNS1、DNS2，配置保存后可以重连成功`
- 拆分为：
  - 用例1：配置 Ethernet1 IP = `192.168.10.50`，保存后重连成功
  - 用例2：配置 Ethernet1 Subnet Mask = `255.255.255.0`，保存后重连成功
  - 用例3：配置 Ethernet1 Gateway = `192.168.10.1`，保存后重连成功
  - 用例4：配置 Ethernet1 DNS1 = `8.8.8.8`，保存后重连成功
  - 用例5：配置 Ethernet1 DNS2 = `1.1.1.1`，保存后重连成功

> 常用测试值参考：IP `192.168.10.50`，Subnet Mask `255.255.255.0`，Gateway `192.168.10.1`，DNS1 `8.8.8.8`，DNS2 `1.1.1.1`

---

### 规则4：正常/异常场景拆分
同一功能的正常场景和异常场景分为独立用例。

**示例：**
- 脑图：`用户名长度限制 1~20 字符`
- 拆分为：
  - 用例1（LV1）：输入合法用户名（1字符、20字符），保存成功
  - 用例2（LV2）：输入0字符（空）或21字符，阻止保存并提示错误

---

### 规则5：强制用例数
脑图分支末尾标有「X个用例」时，必须严格生成 X 条用例，不得增减。

**示例：**
- 脑图：`查看SN、MAC1、MAC2、WiFi MAC是否正确，并保证都是只读状态。2个用例`
- 严格生成2条：
  - 用例1：查看 SN、MAC1、MAC2、WiFi MAC 显示值正确
  - 用例2：验证 SN、MAC1、MAC2、WiFi MAC 均为只读，不可编辑

## 步骤与预期结果写法规范

### 格式
```
测试步骤：
1. <动作描述>
2. <动作描述>
3. <动作描述>

预期结果：
1. <对应步骤1的预期>
2. <对应步骤2的预期>
3. <对应步骤3的预期>
```

### 编号对应规则
- 预期结果编号必须与步骤编号对应
- 预期结果可跳号（如只有步骤2、3有预期，写 `2. xxx  3. xxx`）
- **不得出现编号错位**（如步骤有3步，预期结果编号却从1跳到4）

### 步骤写法要求
- 每步一句话，动词开头，如：`进入`、`输入`、`点击`、`查看`、`配置`
- **动作必须带对象与值**：写 `配置 BACnet Port = 47808`，不写 `配置端口为合法值`；写 `进入 设置 -> 通信 -> BACnet/IP`，不写 `进入相应配置页面`
- **预期必须可判定**：写出具体的值、现象或提示文案，禁止"检查是否正常""验证功能正确""配置生效"式无法判定对错的表述
- 不写大段描述，不在步骤里嵌套子列表
- 超过4步时优先拆分为多个更聚焦的用例（标「是」的自动化用例允许至6步，见下方增强规范）

### 自动化用例步骤增强规范（「是否能自动化」=是 时强制）

标「是」的用例，其步骤文本就是后续自动化转换（如 `acuview_auto_testcase_generate`）提取"设置项/目标值/回读期望/还原值"的唯一信息源。逐条满足：

| # | 要求 | 反面写法（禁止） | 正确写法 |
|---|------|-----------------|---------|
| 1 | **入口写完整路径**：页面/菜单逐级写全 | 进入背光设置页面 | 进入 Setting—Maintenance—LCD Backlight Time |
| 2 | **操作对象唯一化**：配置项/读取项写界面显示全名，一步只操作一个对象 | 配置相关网络参数 | 配置 Ethernet1 IP = 192.168.10.50 |
| 3 | **输入值具体化**：写明目标值与单位；值须在合法范围内且可逆 | 输入一个合法值 | 配置 LCD Backlight Time = 30s（默认 60s） |
| 4 | **验证方式显式化**：预期写清在哪里读、读什么、期望值多少（界面回显 / 协议回读如 Modbus 对应参数 / Web 页显示），数值比对有容差约定的写容差 | 配置生效 | 界面回显 30s；Modbus 回读 LCD Backlight Time 寄存器 = 30 |
| 5 | **写值类用例自带还原**：末步恢复默认值/原值，预期确认还原成功 | （无还原步骤） | 恢复 LCD Backlight Time = 60s，回读确认 = 60 |
| 6 | **物理观察项分离**：无法程序断言的现象（背光变暗、指示灯、蜂鸣）单独成步并标注 `（MANUAL 目视）`，不与可断言步骤混写 | 屏幕变暗且回读值为30 | 观察屏幕背光在 30s 后熄灭（MANUAL 目视） |

**补充规则：**
- 回读途径按项目实际能力写（上位机界面 / Modbus / Web / 北向协议），不确定用哪条链路时写"界面回显 + 协议回读"两条预期，由自动化转换时裁剪
- 一条用例聚焦一个配置项的闭环；多个配置项各自成条（对应"一函数一用例"约定），禁止一条用例批量遍历多个不同对象
- 标「是」但步骤达不到本规范的，要么补全步骤，要么改判「否」并在备注写明——**不允许"标了是、步骤却不可提取"的中间态**

HEADER_FILL  = PatternFill('solid', fgColor='70AD47')   # 绿色 个性色6

def build_excel(cases, output_path, sheet_name):
    wb = openpyxl.Workbook()
    ws = wb.active
    ws.title = sheet_name

    for col_idx, col_name in enumerate(COLUMNS, start=1):
        cell = ws.cell(row=1, column=col_idx, value=col_name)
        cell.font        = HEADER_FONT
        cell.fill        = HEADER_FILL
        cell.alignment   = ALIGN_CENTER
        cell.border      = ALL_BORDERS
        ws.column_dimensions[
            openpyxl.utils.get_column_letter(col_idx)
        ].width = COL_WIDTHS.get(col_name, 16)

    for row_idx, case in enumerate(cases, start=2):
        for col_idx, col_name in enumerate(COLUMNS, start=1):
            value = case.get(col_name, '')
            cell  = ws.cell(row=row_idx, column=col_idx, value=value)
            cell.font      = BOLD_FONT if col_name in BOLD_COLS else NORMAL_FONT
            cell.alignment = ALIGN_WRAP
            cell.border    = ALL_BORDERS

        max_lines = max(
            str(case.get(c, '')).count('\n') + 1
            for c in ['测试步骤', '预期结果', '预置条件']
        )
        ws.row_dimensions[row_idx].height = max(18, max_lines * 18)

    ws.row_dimensions[1].height = 22
    ws.freeze_panes = 'A2'

    wb.save(output_path)
    print(f'已生成：{os.path.abspath(output_path)}')

build_excel(CASES, OUTPUT_PATH, SHEET_NAME)

## 关键注意事项

| 事项 | 说明 |
|------|------|
| 换行符 | 测试步骤/预期结果用 `\n` 分隔，openpyxl 会自动展示为多行（需开启 wrap_text） |
| 表头颜色 | `PatternFill('solid', fgColor='70AD47')` 对应"绿色 个性色6" |
| 加粗列 | 模块、子模块列使用 `BOLD_FONT`，其余列使用 `NORMAL_FONT` |
| 字体 | 全表统一 `微软雅黑 10pt` |
| 边框 | 所有单元格（含表头）使用 `ALL_BORDERS` |
| 输出路径 | `os.path.join(os.getcwd(), '文件名.xlsx')`，输出到当前工作目录，全平台通用 |
| 工作表命名 | 使用当前测试主题，如 `01控制与导航`、`02通信协议` |
| 空列 | 测试结果/负责人/备注/自动化/问题单来源 写入空字符串 `''` |
