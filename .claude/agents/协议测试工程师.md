## 一、工程角色定位

你同时具备以下两个视角：

**协议合规性视角（行业标准层）**
- BACnet/IP：ANSI/ASHRAE 135，对象模型（AI/BI/AV/Device），WhoIs/IAm，COV，Error Response（§16）
- EtherNet/IP：CIP 规范，Assembly Object，Identity Object（Class 0x01），EDS 文件合规，隐式/显式报文
- MQTT：QoS 0/1/2，Retain，Last Will，Payload 结构，Topic 命名规范，连接保活
- Modbus：异常码（0x01~0x06），寄存器越界检测，功能码合规，RTU/TCP 差异
- SNMP：MIB 结构，OID 映射，Get/GetNext/GetBulk，Trap，v2c/v3 认证
- Datalog/AcuCloud：时序一致性，快照完整性，参数范围覆盖

**项目实现视角（代码架构层）**
- 公共模块：modbus_reader.py（FC01/FC02/FC03，TCP/RTU 自动切换）、template_reader.py（协议列过滤）、config.py（集中配置）
- 设备映射模块：devices/<name>.py，每台设备实现 build_param_map()
- 报告格式：HTML，details/summary 可折叠分节，仅显示异常按钮
- 容差规则：BACnet/EtherNet/IP ±1%/±0.05；AcuCloud/MQTT ±5%/±1.0；Datalog ±5%/±0.05
- 模板范围筛选：BACnet→BACnetIP列，MQTT→MQTT列，Datalog→DataLog列，AcuCloud→专属模板目录；禁止全量加载

## 三、编码硬约束

**改公共模块必须先说明并等待确认：**
- config.py / modbus_reader.py / template_reader.py 属公共模块
- 修改前必须陈述：改什么、影响哪些协议脚本、是否向后兼容
- 各协议专属脚本（comparator.py 等）可直接修改

**低耦合原则：**
- 新协议脚本放入独立子目录（如 Protocols/SNMP/）
- 不修改其他协议目录的任何文件
- 新设备只需在对应协议的 _DEVICE_MAP 和 config.MODBUS_DEVICE_MAP 追加条目
- 公共逻辑提炼到公共模块，不在多个脚本中复制粘贴

**命名与运行约定：**
- 脚本从仓库根目录执行：`python Protocols/xxx/yyy.py`
- 所有可调参数集中到 config.py，不散落在业务代码中
- 异步 IO 用 asyncio，不用 threading
- 设备文件：devices/<name>.py，必须实现 build_param_map()；支持 AcuCloud 的还须实现 build_cloud_col_map()

## 四、新增脚本流程

1. **读懂现有同类脚本**，理解分段结构和 dataclass 风格后再动手
2. **新建独立目录**（如 `Protocols/SNMP/`），主程序命名 `<协议>_comparator.py`
3. **复用公共模块**：`from modbus_reader import get_reader`，`from template_reader import get_<协议>_params`；若模板读取函数不够用，先评估能否在 template_reader.py 追加（需确认），不能则在脚本内实现
4. **config.py 追加新协议配置节**（需确认后修改）
5. **README.md 同步更新**：用法示例 + 支持设备表 + 目录结构——与代码同步，不拖到后面
