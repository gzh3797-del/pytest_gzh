> 状态：**待组内评审**。评审通过后作为全工程合入门禁依据，并在 CLAUDE.md「高频约定」与 conventions.md 加指针。
> 适用范围：`autotest` 工程下所有项目（`projects/<项目>/`）的自动化用例产出，含手写与 AI 生成（acuview_auto_testcase_generate 等 skill 产出同样受约束）。
> 本规范整合了既有分散约定（knowledge/shared/conventions.md、CLAUDE.md 高频约定、README.md 目录分工），冲突处以本文为准；本文未覆盖的细节仍以 conventions.md 为准。

## 1. 框架选型（已定，不再各选各的）

| 层 | 统一选型 | 说明 |
|---|---|---|
| 测试框架 | pytest（根 pytest.ini 统一配置） | 禁止模块自带 pytest.ini 覆盖根配置 |
| Web UI | Playwright sync API | 编码细则见 conventions.md「Playwright UI 测试编码约定」 |
| 上位机 GUI | comm/ctl_acuview 引擎（pyautogui/OpenCV/OCR） | 由 acuview_auto_testcase_generate skill 驱动生成 |
| 通信/台架 | comm/（Modbus、源控制、继电器、SSH、串口） | 只允许 `from comm.xxx` 导入，禁止私拷贝 |
| 协议比对 | tools/Protocols/ 比对引擎 | 从仓库根执行，`python tools/Protocols/...` |
| 基建 | framework/（config/logging/report/retry/assertion/runner） | 报告路径、配置合并一律走 framework |
| 报告 | pytest-html 自包含 HTML（根 conftest 统一重定向目录） | 禁止 allure 等私搭报告栈 |
| Python | 3.10+；IO 密集用 asyncio，不用 threading | 见 conventions.md「通用」 |

新增第三方依赖必须写入根 `requirements.txt` 并在 PR/合入说明中注明用途；禁止模块内隐性依赖。

## 2. 目录结构规范

### 2.1 项目骨架（以 projects/acuhmi_1_7 为样板）

```
projects/<项目>/
├── README.md            # 模块索引
├── config.yaml          # 项目配置（project_name、设备 IP 等差异项）
├── conftest.py          # 项目级 fixture（仅一处）
├── tests/               # 全部用例，按模块/协议分子目录
│   └── <模块>/          # 见 2.2 命名规则
├── pages/               # UI Page Object
├── helpers/             # 项目内业务辅助
├── data/                # 测试数据
└── utils/               # 项目内通用工具
```

### 2.2 tests/ 子目录命名

- **全小写 snake_case**，禁止空格、禁止大小写混排。
  - ✅ `aws_iot`、`data_log`、`bacnet_ip`、`wiring_check`、`device_mirror`
  - ❌ `Device Mirror`（空格）、`Pass Through`（空格）、`BacnetIP`、`SNMP`、`Wiring_check`
- UI 用例统一放 `tests/ui/<一级模块>/<二级功能>/`，一级模块目录名与选择器沉淀文档名对应（高频约定 11）。
- 目录层级最深到 `tests/<模块>/<子模块>/`，再深说明拆分有问题。

### 2.3 模块目录内禁止出现

| 禁止项 | 原因 | 正确做法 |
|---|---|---|
| 模块私有 `pytest.ini` | 覆盖根配置，marker/收集行为分裂 | 需要新 marker → 在根 pytest.ini 注册 |
| 模块私有 `reports/`、`*.html` 报告 | 报告统一落 `reports/<项目>/<时间戳>/` | 由根 conftest / framework runner 自动归位 |
| `.pytest_cache/`、`__pycache__/`、`*.pyc` 入库 | 纯本地产物 | 确认 .gitignore 覆盖 |
| 证书私钥、口令明文（`*.pem.key`、`*-private.*`） | 敏感信息入库 | 路径写 config，文件放 `configs/.env` 指向的库外位置或 gitignore 目录 |
| 一次性调试脚本、`_tmp_*`、临时 JSON/txt | 知识库禁止操作第 1 条（最高优先级） | 任务结束前删除，零残留 |
| `open_report.bat`、`start_server.vbs` 类私有启动脚本 | 各自为战的入口 | 通用的进 `tools/` 或 framework，模块 README 写命令 |

## 3. 命名与编号规范

### 3.1 用例编号是唯一主键

- 代码中的用例编号必须与测试用例 Excel「用例编号」列**逐字符严格一致**（前缀、分隔符、顺序），一编号一用例（高频约定 12）。
- 回填结果永不改动用例表编号列；发现不匹配 → 整理清单（报告编号 ↔ 用例表编号 ↔ 差异类型）交负责人改**代码侧**。
- 禁止出现的差异（2026-07 回填实际踩过）：项目前缀不一致、编号/名称顺序颠倒、分隔符 `_`/`-` 混用、`_row598`/`_v2` 冗余后缀。

### 3.2 文件 / 类 / 函数命名

根 pytest.ini 只收集 `test_*.py` 和 `TestCase_*.py`。**全工程统一采用风格 A，不再两种风格并存**：

- **风格 A（编号在文件名 + 类名，唯一标准，一文件一用例）**：
  - 文件：`TestCase_<项目>_<模块>_<编号>.py`（如 `TestCase_AcuHMI-1-7_AWS_004_001.py`）
  - 类：`TestCase_<项目>_<模块>_<编号>`（一文件一用例）
  - 类名分隔符合法映射：Python 类名不能含 `-`，文件名里的 `-` 在类名中一律用 `_` 替代（文件 `TestCase_AcuHMI-1-7_...` ↔ 类 `TestCase_AcuHMI_1_7_...`）；逐字符回溯**以文件名为准**。

硬性要求：**用例编号必须完整出现在 pytest nodeid 中**（体现在文件名+类名中），保证报告能逐字符回溯到用例表。

> 决策已定（2026-07）：本稿收敛为**风格 A**，风格 B 不再使用。全工程统一（同步 CLAUDE.md 高频约定 10、conventions.md「pytest 用例命名约定」——两者现为风格 B）待本评审稿通过后再同步；存量风格 B 用例（UI/参数设置类，如 `test_013_01_case01`）改造属"改代码侧 ID"、影响历史报告对比，排期评审会定。

### 3.3 其他命名

- 图像匹配模板文件名**纯 ASCII**（pyautogui/cv2 中文路径静默失败，见 conventions.md）。
- 设备地址表模块：`devices/<设备名小写>.py`。
- 页面对象：`pages/` 下一页一类，类名 `<Page>Page`。

## 4. 用例文件内容规范

### 4.1 文件头 docstring（必填六项：编号 / 标题 / 级别 / 预置条件 / 步骤 / 预期结果）

沿用 aws_iot 与 acuview 引擎既有格式，每个用例文件顶部：

```python
"""
用例编号: <与用例表逐字符一致，如 FTS_AcuHMI_AWS_004_001>
用例标题: <一句话>
用例级别: <LV0/LV1/LV2/LV4，与用例表优先级对应>
预置条件:
  - <条目>
测试步骤:
  1. <步骤>
预期结果:
  - <可断言的结果>
"""
```

### 4.2 marker 规范

- 只允许使用根 pytest.ini 已注册的 marker；新增先注册再使用。
- 每条用例至少打：**级别 marker**（lv0/lv1/lv2/lv4 或 smoke/critical）+ **模块 marker**（如 aws_iot）。
- 改变设备状态的用例必须打 `destructive`；超过 5 分钟的打 `slow`。

### 4.3 断言与结构

- 断言必须带失败说明：`assert x == y, f"...实际：{x!r}"`；禁止裸 `assert func()`。
- 数值比对一律走容差断言（BACnet ±1%/±0.05，AcuCloud ±5%/±1.0，见高频约定 2），禁止浮点直等。
- 环境准备/清理放 fixture（项目 conftest.py 或模块 conftest.py），测试体只写 步骤+断言；改了设备配置的用例必须在 fixture teardown 中还原。
- 连接类资源（Modbus、浏览器、SSH）只从 fixture 获取，禁止测试体内裸建连接。
- 测试体内禁止 `asyncio.run()`（Playwright 场景用 `_run_coro` 线程模式）。
- 禁止 `time.sleep` 裸等待代替条件等待（Playwright 用 expect 自动等待；协议场景用轮询+超时封装）。

## 5. 配置与敏感信息

- 三层合并唯一来源：`configs/global.yaml` ← `projects/<项目>/config.yaml` ← `configs/.env`；禁止模块私有 config.yaml 另起一套（模块确有专属配置项 → 并入项目 config.yaml 的模块段）。
- 口令、证书、token 一律走 `configs/.env`（不入库）；仓库内只允许出现公开 CA 证书。
- 用例代码中禁止硬编码 IP/端口/口令，一律从 config fixture 读取。

## 6. 报告与产物

- 报告统一落 `reports/<项目>/<时间戳>/{html, screenshots, logs}`，由根 conftest / framework runner 自动归位，模块不自建报告目录。
- 失败必须留证据：UI 用例失败自动截图进 `screenshots/`；协议用例失败日志中必须含发送/接收原始数据。
- 运行产物（spec_acuview/、reports_acuview/ 等可重建目录）全部 gitignore。

## 7. 模块交付配套（模块 README / 项目配置 / 项目入口命令）

单个模块用例输出完成后，除用例代码本身外，必须同步交付以下三项，**缺一不得合入**：

### 7.1 模块 README（`tests/<模块>/README.md`）

每个模块目录必须有详细 README，固定包含四部分（标题与顺序统一，便于评审与检索）：

```markdown
# <模块名> 自动化用例

## 模块逻辑
<被测功能简介、测试思路（如：下发→回读→跨协议比对）、用例覆盖范围、用例编号区间或清单>

## 执行前提
- <设备型号 / 固件版本要求>
- <网络与连接要求（IP 可达、需开启的协议服务、下挂设备等）>
- <其他预置条件（账号、证书已配置、时间同步等）>

## 配置信息位置
- 模块配置：`projects/<项目>/config.yaml` 的 `<模块段名>` 段（逐项说明各配置项含义）
- 敏感信息：`configs/.env` 的 `<键名>`（只写键名，禁止在 README 出现口令/密钥明文）

## 执行命令
# 从仓库根目录执行
pytest projects/<项目>/tests/<模块>/                # 全量
pytest projects/<项目>/tests/<模块>/ -m lv0         # 按级别 marker
pytest projects/<项目>/tests/<模块>/<单文件或 nodeid> # 单条用例示例
```

### 7.2 项目 config.yaml 模块配置段

- 模块专属配置项一律并入 `projects/<项目>/config.yaml`，以模块名为顶层段（段名与 `tests/` 下模块目录名一致，snake_case），禁止模块私有 config.yaml（与第 5 节一致）。
- 段内配置项加行内注释说明含义与取值来源；口令、证书、token 仍走 `configs/.env`，config.yaml 中只写引用键名或库外路径。

```yaml
# projects/<项目>/config.yaml
<模块段名>:            # 与 tests/<模块> 目录名一致
  host: 192.168.1.100  # 被测设备 IP
  port: 502            # 服务端口
  # 敏感项走 configs/.env，此处不出现明文
```

### 7.3 项目 README 执行命令

- 在 `projects/<项目>/README.md` 的模块索引中新增该模块行，统一格式：

```markdown
| 模块 | 说明 | 详细文档 | 执行命令 |
|---|---|---|---|
| <模块名> | <一句话说明> | [README](tests/<模块>/README.md) | `pytest projects/<项目>/tests/<模块>/` |
```

- 执行命令必须与模块 README「执行命令」一节一致，且从仓库根目录可直接执行。

## 8. 代码质量门禁

- 所有 Python 代码 **PyCharm 零告警**（PEP 8、未使用 import/变量、类型注解不一致），硬性要求（高频约定 8）。
- Playwright 编码约定（locator+expect 优先、坐标点击降级条件、可见性过滤等）按 conventions.md 执行。
- 写/调试 UI 用例前必须先查选择器沉淀文档，命中即复用（高频约定 11）。
