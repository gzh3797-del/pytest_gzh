# AI 工作流总纲

> 本目录存放组内 AI 辅助测试工作流。本文只讲**所有工作流通用**的概念与规则；
> 单条工作流的启动话术、阶段细节、产物位置见其配套使用说明（`<工作流名>_使用说明.md`）。

## 工作流是什么

一套写在声明文件（YAML）里的 AI 辅助流程：把一类测试工作拆成固定阶段链，每段声明——执行者是 AI 还是人（`executor`）、用哪个 skill（`tool`）、输入输出、过门标准（`gate`）、不过门怎么回炉（`on_fail`）。AI 干机械活（生成/查漏/比对/记账），人只在 gate 处裁决。

核心设计：**流程状态在文件里，不在对话记忆里**——任何 Claude Code 会话读了 YAML 就能执行或接力，中断不丢、换人不断。

## 通用规则（所有工作流一致）

1. **启动**：对 Claude Code 说 `/run-workflow <工作流名> + 各输入参数`（由 `.claude/skills/run-workflow` 统一执行）；说"按 knowledge/shared/workflows/<工作流名>/workflow.yaml 执行"效果相同。输入不齐不启动。
2. **范围限定**：支持"范围：仅 XX，其余不处理"限定到单模块/单章节，全链只处理该范围。
3. **续跑**：说"从 S<N> 继续 + 已完成阶段的产物路径"，任何会话/任何人可接力。
4. **gate 打勾权归人**：验收清单复选框一律留空呈现，AI 只给自查证据；审核人必须明确回复（通过/回炉/自定义），沉默不放行。
5. **人工改产物**：先保存并关闭文件，再告知 AI"已手改，重新读取"；AI 合并改动前必须先做重叠判定并经确认。
6. **运行记账**：每单结束由收尾阶段归档到 `runs/`（采纳率原料、人时、回炉原因），人时当场向执行人询问。

## 目录约定

```
workflows/
├── README.md                      # 本文（总纲，不写单工作流细节）
├── <工作流名>/                     # 一条工作流一个文件夹
│   ├── workflow.yaml              #   声明文件（给 AI 执行的"法律文本"，文件名固定）
│   └── 使用说明.md                 #   配套使用说明（给组员看，文件名固定）
└── runs/                          # 运行记录归档（中央目录，文件名带工作流名，便于跨工作流汇总）
```

**新增工作流规则**：新建 `workflows/<工作流名>/` 文件夹，内部文件名固定为 `workflow.yaml` + `使用说明.md`（**两件套缺一不得登记**，寻址靠固定文件名，同 `.claude/skills/<名>/SKILL.md` 模式）；完成后在下方登记表加一行。修改现有工作流的 stages/gate 属于流程变更，需 owner 评审。
