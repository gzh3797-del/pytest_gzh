# 手工用例转自动化-WebUI · 使用说明

> 声明文件：同目录 `workflow.yaml`（流程以 YAML 为准，本文是操作指引）
> 通用规则（gate 打勾权、续跑、记账等）见 [../README.md](../README.md)，本文不重复。
> 业务实现：`.claude/skills/webtestcase_manual_to_auto/`（本工作流只做外壳，不改 skill）

## 干什么用

把 Web UI 手工用例 Excel 转成 Playwright+pytest 自动化脚本。相比直接调用
`/webtestcase_manual_to_auto`，本工作流多了：

```
S1 分析染色(AI, --analyze-only) → S2 红色用例澄清【门禁】
→ S3 生成+覆盖门禁+运行调试+回填+沉淀(AI) → S4 覆盖门禁与结果验收【门禁】 → S5 运行记账(AI)
```

- **入口校验**：Excel/项目映射/页面可访问性不齐不启动
- **两道人工门禁**：S2 卡"红色用例澄清清楚了没"，S4 卡"覆盖到位没、脚本语义对不对"
- **每单留痕**：转换率/门禁首评通过率/红色澄清转化率/人时进 `runs/`

> skill 自带的严禁编造铁律、Step 4.5 五道覆盖门禁、Gate E 语义对照矩阵保持权威，
> 本工作流不弱化——S2/S4 是在其基础上的工程级验收留痕。

## 启动话术

**单模块（常用）：**
```
/run-workflow 手工用例转自动化-WebUI
项目：AcuHMI_1_7
用例集：knowledge/gateway/hmi1-7/testcase/【AcuHMI-1-7】项目软件全功能测试用例xxx.xlsx
范围：仅「用户管理」模块
```

**多模块 / 单条：**
```
范围：模块「用户管理」「系统设置」        # 对应 skill --module A B
范围：仅用例 TestCase_AcuHMI_009_08_case01  # 对应 skill --case
```

**中断续跑：**
```
/run-workflow 手工用例转自动化-WebUI 从 S3 继续
项目：AcuHMI_1_7
说明：红色用例已在「用户答复」列澄清完毕
```

## 门禁怎么回复

- **S2（红色澄清）**：AI 给你待澄清清单（用例编号 → 根因/疑问）。你在 Excel「用户答复」列填写，
  或对话回复，然后 `S2 通过，进 S3` / `TC-12 本期不自动化，豁免`。
- **S4（覆盖与结果）**：AI 给你覆盖门禁结论 + Gate E 对照矩阵 + pytest 结果。回复
  `S4 通过` / `TC-05 少验了预期第 2 行，补断言重跑` / `TC-09 角色错配，view 写成了 edit`。

## 审核时先看什么

1. **Gate E 语义对照矩阵**：逐条比对步骤/预期的关键参数（谁登录、什么角色、填什么值、断言什么）
   与代码是否语义一致——"有代码"不等于"对"，角色 view↔edit、填错谁的密码这类最常见。
2. **覆盖零漏项**：每条步骤都有操作、每条预期都有断言，不接受"综合断言""只验第一行"。
3. **配置还原（Gate D）**：改了开关/模式/阈值/通信参数的用例，必须在 finally 逐项还原原值。
4. **无探查脚本残留**：探查一律走 webpage_analyze skill，项目目录零一次性脚本残留。

## 产物位置

- 脚本：`projects/<项目>/tests/<自动化类型>/`
- Excel 回填 3 个 Claude 列（不动原始 A–P 列，不动用例编号列）
- 选择器沉淀：`<knowledge_root>/requirements/context/*_context.md`
- 运行记录：`knowledge/shared/workflows/runs/`

## 结束时

S5 会当场问你这单实际投入的人时，请如实回答——转换率/门禁通过率/人时是评估收益的核心数据。
