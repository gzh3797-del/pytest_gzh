# 用例设计工作流 · 使用说明

> 声明文件：同目录 `workflow.yaml`（流程以 YAML 为准，本文是操作指引）
> 通用规则（gate 打勾权、续跑、记账等）见 [../README.md](../README.md)，本文不重复。

## 干什么用

把"需求文档 → 测试点脑图 → 测试用例 Excel"做成固定流程：

```
S1 测试点生成(AI: strategy-design) → S2 查漏(AI: coverage-check)
→ S3 人工审核【门禁】 → S4 用例生成(AI: testcase-design) → S5 查漏(AI)
→ S6 人工审核【门禁】 → S7 运行记录归档(AI)
```

相比直接让 AI"帮我写用例"，它多了：知识库强制读取（设备型号/编号区间/历史bug/跨项目基线，以「知识库提取表」为证据）、独立查漏复核、两道人工门禁、每单留痕。

## 启动话术

> 统一推荐以 `/run-workflow 用例设计` 开头；旧长写法（"按 knowledge/shared/workflows/用例设计/workflow.yaml 执行"/"从 S<N> 继续"）仍被识别、效果等效，无需迁移已有习惯。

**整份需求：**
```
/run-workflow 用例设计
项目：<项目名，如 acuhmi_1_7>
需求文档：<路径，如 requirements/summaries/v2.00_20260519.md>
```

**只做单模块（常用）**——范围要封闭（"仅…其余不处理"）：
```
/run-workflow 用例设计
项目：acuhmi_1_7
需求文档：requirements/summaries/v2.00_20260519.md
范围：仅 §3.4 SNMP 模块，其余模块不处理
```

**中断续跑（换会话/隔天）**——说清从哪段继续 + 已完成产物路径：
```
/run-workflow 用例设计 从 S4 继续
项目：acuhmi_1_7
审定脑图：projects/acuhmi_1_7/testcase/xxx_测试策略.xmind
```
（S3 没审完就写"从 S3 继续，脑图在 <路径>"，以此类推。）

## 门禁（S3/S6）怎么回复

AI 停下来后给你：产物路径 + 查漏结论 + 留空验收清单。三选一：

- **通过**：`S3 通过，进 S4`（带一句改了什么，如"补了 3 条边界"——采纳率数据来源）
- **回炉**：`第 2 条不过，把查漏 #5/#7 补进脑图，重跑查漏再交审`
- **自己改了文件**：保存并关闭 XMind/Excel 后说：
  `我已手补并保存，重新读取文件；把查漏 🔴 项也补进去，先和我手补的做重叠判定、
  列清单给我确认，别重复添加；补完重跑查漏、重发验收清单`

嫌逐条核对麻烦，可以让 AI 先干体力活：`第 1 条你先自查，把需求点↔测试点对照表列出来，缺的标出来`——AI 摆证据，你只裁决。

## 审核时先看什么

1. **「知识库提取表」**：起草前 AI 必交（设备清单/协议端口/编号区间/跨项目基线等九~十类）。哪栏空着而知识库里明明有 = 漏读，当场打回。
2. **设备型号**：测试点/用例出现"设备""电表"泛称直接判不过（必须是 AcuRev4100、AcuIOM-01 这样的具体型号）。
3. AI 自查通过 ≠ 审核通过：它的 `✅` 只是证据，勾由你打。

## 产物位置

- 脑图 + 用例 Excel + 摘要 .md：`projects/<项目>/testcase/`
- 运行记录：`knowledge/shared/workflows/runs/`

## 结束时

S7 会当场问你这单实际投入的人时，请如实回答——季度末证明 AI 化收益全靠这组数据。
