# 手工用例转自动化-电表Acuview · 使用说明

> 声明文件：同目录 `workflow.yaml`（流程以 YAML 为准，本文是操作指引）
> 通用规则（gate 打勾权、续跑、记账等）见 [../README.md](../README.md)，本文不重复。
> 业务实现：`.claude/skills/acuview_auto_testcase_generate/`（本工作流只做外壳，不改 skill）

## 干什么用

把电表项目 `manual_testcase/*.xlsx` 的手工用例，转成驱动 Acuview2 上位机 + Modbus 回读比对的
pytest 自动化用例。相比直接调用 `/acuview_auto_testcase_generate`，本工作流多了：

```
S1 建模+读用例+逐条定位(AI) → S2 映射与安全确认【门禁】
→ S3 生成+运行+回填(AI) → S4 转换结果验收【门禁】 → S5 运行记账(AI)
```

- **入口校验**：spec 原料/config/上位机不齐不启动，不会跑到一半才发现缺文件
- **两道人工门禁**：S2 卡住"映射对不对、写寄存器安不安全"，S4 卡住"转换结果可不可信"
- **每单留痕**：转换率/首通率/定位失败率/疑似 bug/人时进 `runs/`，季度末证明 AI 化收益

> skill 自带的 🔴 映射确认 checkpoint（第 4.4 步）是安全铁律，本工作流不弱化它——S2 是在其
> 基础上的工程级验收留痕。

## 启动话术

**整份可自动化用例：**
```
/run-workflow 手工用例转自动化-电表Acuview
项目：RPP
手工用例：projects/RPP/manual_testcase/xxx.xlsx
```

**只做某用例段（常用）**——范围要封闭：
```
/run-workflow 手工用例转自动化-电表Acuview
项目：RPP
手工用例：projects/RPP/manual_testcase/xxx.xlsx
范围：仅 Function_RPP_027_* 段，read 类暂不处理
```

**中断续跑：**
```
/run-workflow 手工用例转自动化-电表Acuview 从 S3 继续
项目：RPP
已确认映射：<S2 产出的映射清单路径或对话确认记录>
```

## 门禁怎么回复

- **S2（映射与安全）**：AI 给你每条用例的候选 register/page/widget + 安全校验证据。回复
  `S2 通过，进 S3` / `第 3 条 widget 选错，应是 <X>` / `<某寄存器> 在禁写清单，该条中止`。
- **S4（转换结果）**：AI 给你 pytest 结果 + 逐条回读值 vs 目标值 + skip 原因。回复
  `S4 通过` / `TC-05 回读≠目标疑似 bug，单独报` / `TC-08 重生成`。

## 审核时先看什么

1. **写类用例的安全**：目标寄存器不在 `safety.forbid_write_*`（通信链路寄存器写了会失联），
   目标值落在 `range` 内且可逆、用例自带还原。
2. **回读≠目标值**：这类是疑似产品 bug，绝不能被 AI 改断言凑通过——必须单独列出报负责人。
3. **设备未还原告警**：跑挂的写类用例可能把设备停在非默认状态，S4 若有此告警先手动恢复再继续。

## 产物位置

- 用例文件：`projects/<项目>/tests/acuview_auto/`
- 手工 xlsx 回填「测试结果」「调试结果」列（原始其余列不动）
- 运行记录：`knowledge/shared/workflows/runs/`

## 结束时

S5 会当场问你这单实际投入的人时，请如实回答——转换率/首通率/人时是评估收益的核心数据。
